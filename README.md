# 研序 Research Workspace

面向第九届传智杯AI大模型创新应用挑战赛的科研助手项目。以论文原文和可定位证据为基础，逐步实现解析、问答、阅读翻译、检索推荐、引用图谱与学术写作。

## 当前阶段

项目于2026年10月8日启动。目前已实现首阶段的本地文献库、持久后台解析、页面图像、原文检索与区域定位接口，并提供浏览器工作台。后端测试和实际浏览器流程均已验证，结果与范围见下文。

当前流程：上传PDF → 后台逐页提取文字 → 查看文献和页面 → 检索原文 → 点击结果定位原文区域。尚未完成比赛六大模块，官方测试资料包尚未取得。

已实现的基础能力：

- 校验PDF并保存原始文件，以SHA-256识别完全相同的文件；同名不同文件不会直接覆盖。
- SQLite保存任务、页面文本和坐标；独立解析进程逐页处理，重启后恢复中断任务。
- 重新提取产生独立解析记录，保留原文件和旧证据；新任务处理中或全部失败时，默认读取已有可用结果。
- 原文关键词检索返回文献、解析记录、物理页码及区域坐标；页面图像与坐标使用一致的显示方向。
- 分别显示已提取、部分完成、无可提取文本和失败状态，避免把空文本当成完整解析。

## Windows运行

使用Python 3.12和PowerShell，以下命令均在项目根目录执行。当前工作区的依赖已按授权安装到 `.venv`，并已通过 `pip check`，可以直接启动；不必重复安装。

新环境首次准备时，先确认已安装Python 3.12。若提供Windows Python启动器，可运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip check
```

若没有 `py` 启动器，使用已安装Python 3.12解释器的绝对路径执行 `-m venv .venv`。本项目不依赖系统默认的 `python` 命令，也不要求激活虚拟环境。仅运行应用时可安装 `requirements.txt`；开发与测试使用包含运行依赖的 `requirements-dev.txt`。

启动：

```powershell
.\scripts\start.ps1
```

浏览器访问 [http://127.0.0.1:8765](http://127.0.0.1:8765)。需要其他本地端口时使用 `.\scripts\start.ps1 -Port 8766`，端口范围为1024至65535。启动脚本实际执行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn research_workspace.api:app --host 127.0.0.1 --port 8765 --workers 1
```

保持启动终端运行；在该终端按 `Ctrl+C` 停止服务，应用会同时停止其解析子进程。关闭网页不会停止服务。若启动脚本被本机执行策略拦截，可直接使用上面的等效命令，无需修改全局执行策略。

本阶段固定为一个应用进程和一个独立解析进程。不要增加Uvicorn工作进程、对同一数据目录重复启动服务，或改为 `0.0.0.0`。同源与Host检查只服务于本机边界；当前没有用户认证或多用户隔离，不适合公网或局域网共享部署。

## 配置与运行数据

应用从进程环境变量读取配置。`.env.example` 只是说明模板，启动脚本和应用**不会自动加载 `.env` 文件**。如需调整，在启动服务的同一个PowerShell会话中设置：

```powershell
$env:RESEARCH_DATA_DIR = Join-Path (Get-Location) 'data'
$env:RESEARCH_MAX_UPLOAD_MB = '50'
.\scripts\start.ps1
```

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `RESEARCH_DATA_DIR` | 项目根目录下的 `data/` | 原始PDF、数据库、解析记录及worker日志的位置；自定义目录建议使用绝对路径 |
| `RESEARCH_MAX_UPLOAD_MB` | `50` | 单文件上限，按MiB计算，即50×1024×1024字节；有效整数范围为1至200 |

上传端另设包含multipart开销的请求体上限；无Content-Length的请求也受实际读取字节数限制。配置修改后需要重启服务。

数据目录中，`originals/`保存不可直接覆盖的原始PDF，`library.sqlite3`保存文献、解析版本、页文本和坐标，`worker.log`记录后台日志。数据不会随Git提交自动备份。

备份前先停止应用及解析进程，再将整个实际数据目录复制到新的备份位置；不要在运行期间只复制 `library.sqlite3` 而遗漏SQLite的WAL等伴随文件。恢复时同样先停止服务，保留现有目录，再指定或恢复完整的数据目录。更换或清空数据库会失去对应证据记录，即使原始PDF仍存在。

后台进程异常退出时不会自动拉起。若任务长期没有进展，可查看 `/api/health` 的 `worker_running` 和数据目录中的 `worker.log`，停止并重新启动服务。恢复会跳过同一任务中已经成功保存的页面；这是服务重启恢复能力，不是持续自动故障切换。

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m pip check
```

2026年10月8日记录的后端结果为31项测试通过，覆盖上传与流式上限、Host/Origin边界、文件重复、任务恢复、历史证据、中文及字面检索、部分失败、541页合成文档，以及旋转和裁剪后的坐标定位。TestClient出现一条Starlette针对httpx的弃用提醒；当前不影响结果，后续依赖升级需重新验证。

另有公开来源的Transformer v1/v7论文和541页《Understanding Deep Learning》进行真实文档基准。教材记录为537页有可提取文本、4页无可提取文本、0页失败，因此状态为部分完成。耗时、内存、来源与验证方法见[PDF文献库与原文证据服务记录](docs/development/002-document-evidence.md)。这些样例不是比赛官方资料包，结果也不代表语义理解、OCR或官方全部测试通过。

准备好本地PDF样本后，可在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\benchmark_samples.py data\samples
```

该脚本读取指定目录中的PDF，不自动下载样本；每次在 `artifacts/benchmarks/` 创建新目录，保存独立数据库和 `results.json`，不覆盖先前结果。脚本抽样检查首部、中部、末页的字面检索和图像输出，不能代替人工检查阅读顺序、内容完整性或检索准确率。样本和基准产物均不进入Git仓库。

实际浏览器验证覆盖批量导入、重复识别、跨文献及当前文献检索、区域高亮、无结果状态、翻页和重新解析历史。桌面1440×1000与手机390×844布局已检查，浏览器脚本及控制台错误均为0。复现方式和边界见[工作台验证记录](docs/development/003-browser-workspace.md)。

## 当前限制

- 未接入OCR或大语言模型；没有把文献内容发送到外部模型服务。原文检索不能称为RAG问答。
- 无可提取文字的文档标记为 `needs_ocr`，单页记录为 `no_extractable_text`。可能是扫描图像，也可能是空白页；该状态不等于已经完成OCR诊断或识别。
- 当前是原生文本块提取，没有完成作者机构、标题树、公式、表格结构、参考文献与附录的细粒度解析；双栏阅读顺序仍需逐例验证。
- 完全重复识别只针对文件字节；未实现正文语义去重、同一论文版本识别或版本差异总结。重新解析记录也不等于论文版本管理。
- 检索为文本块内的字面匹配，统一大小写和空白；不提供语义检索、相关性排名或跨块拼接搜索。坐标定位到文本块，不保证逐词高亮。
- 新解析全部失败或仍在处理时保留旧可用结果；新的部分完成记录可能成为默认可用结果，检索范围以该记录的成功页面为准，历史记录仍保留。
- 暂不支持加密或需密码的PDF；损坏文件会拒绝或记录页面失败。超大页面图像受渲染像素上限约束。
- 单工作空间、无认证、单解析进程；未提供文献删除和完整CRUD、翻译、自动检索推荐、引用图谱、写作与CSV绘图等后续功能，也未发布公网系统。
- 长文档已有工程验证，但单次基准耗时和内存不是所有文档的性能保证；当前尚未通过完整比赛验收。
