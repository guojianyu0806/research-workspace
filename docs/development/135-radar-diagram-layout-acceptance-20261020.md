## worker关闭失败与重测

首次完整回归的`test_service_worker_startup_uses_null_stdin_and_stops_actual_tree`在服务关闭后仍观察到未结束的原进程对象；清理时另出现Windows错误5。旧流程只等待启动器，不能将终止请求返回视作所有真实子进程已经退出。

`7282612`使API所属Windows worker从启动起保留原进程对象、创建与退出时间，持续观察后代关系。关闭按原句柄终止，等待退出信号并复扫关闭期间出现的后代；不按可复用PID清理其他任务。已结束启动器的原后代仍能被识别，失败时保留身份供明确重试，两个worker分别尝试关闭，不因一个失败跳过另一个。没有把等待放入断言前掩盖现象，也未放宽原用例要求。

36项worker/API/模型配置回归通过。另开3组同时执行的worker测试，共15项全部通过；每组均包含实际API崩溃、正常关闭及“受管启动器已退出而原子进程仍活动”的反例，检查原进程在回退清理前均退出，证据在`artifacts/worker-lifecycle/20261020-a4657a2b/`。这不替代121方案S6的长时间混合负载；新重型通道加入后仍须再次持续压力验收。
