# 演示服务的显式后台执行开关

日期：2026-10-30。范围：真实页面演示 v5 的本地启动准备；不代表已完成录屏或真实模型运行验收。

## 原因

既有 `scripts/run_submission_demo.py` 专用于历史结果回看，以 `create_app(..., start_worker=False)` 启动隔离演示空间。配置模型只更新当前服务进程内的临时配置；配置回调也遵守该启动开关，因此不会启动研究任务 worker。创建研究任务仅写入持久队列，不会同步执行。

解析由 `research_workspace.worker` 处理，问答、比较、翻译和论文框架由 `research_workspace.activity_worker` 处理。原有启动方式下，模型显示已配置与后台任务能执行是两个不同状态。

## 改动

启动器新增 `--enable-worker`，仅在显式传入时启用应用已有的后台解析及研究任务流程。默认仍为关闭，保留历史回看时不运行排队任务的行为。隔离空间路径、清单文件及独立端口检查继续生效；服务仍只绑定 `127.0.0.1`。

启动时继续清空继承的模型配置，密钥不写入文件、不从旧进程或聊天提取。启用后台执行并重启现有演示服务后，须由用户在该服务的“模型设置”中重新应用配置，研究 worker 随正常配置回调获得临时配置。

拟执行命令如下；本文编写阶段未运行服务：

```powershell
.venv\Scripts\python.exe scripts\run_submission_demo.py --data-dir artifacts\submission-video-20261030\demo-data-v1 --port 8776 --enable-worker
```

正式重启前应核对没有运行中或排队中的研究任务、订阅及解析任务，防止意外执行已有工作；保留演示数据快照。重启与配置后的实际健康状态由主流程记录，不将本次语法检查当作后台运行证据。
