# 离线多语编码器与输入覆盖验收

日期：2026年10月20日。对应121方案S3的编码基础阶段，接续142下载收据。

## 实现

新增`research_workspace/multilingual_model.py`，读取独立运行清单，首次使用前校验六文件摘要。模型、revision、维数、输入上限、分块规则和文件清单绑定独立指纹；模型路径必须位于已授权的项目目录。已加载适配器拒绝更改后的清单，缺失或无效模型不会隐式下载。

模型输入上限为128 token，不能直接套用现有英文1600字符片段。新增分块按实际分词器的字符offset提出边界，对每个原文子串重新分词并验证含特殊token的总长度；保留完整原文字符范围和24 token的目标重叠，兼顾中文、组合字符及emoji重复offset。返回完整末尾覆盖，不改写原文本身。分块器拒绝已经开启截断或填充的分词器；编码器拒绝超长输入，而不是静默截断。真实编码使用本地FastEmbed及CPU，检查输出数量、384维、有限值及归一化。

该适配器尚未替换英文`SemanticIndex`、阅读区或去重入口。128-token向量需新建独立索引及来源键，不能因为维数相同复用旧向量。这里没有把启动测试冒充索引隔离和跨账号缓存验收。

- 合同测试：`tests/test_multilingual_model.py`，22项通过。使用明确标注的测试分词器验证8语及emoji长文本完整字符覆盖、实际重分词长度、空白边界、无效上限、潜在截断状态、模型字节校验、清单变化和路径逃逸；这些测试不证明真实权重检索质量。
- 实际权重离线运行：`artifacts/multilingual-model/20261020T024741242794Z/report.json`，60项检查通过。封锁Python的connect/connect_ex/getaddrinfo，连接尝试0；真实模型产生12个384维有限归一化向量，英文和多语六文件摘要前后相同，付费调用0。128-token原文切片覆盖至最后`TAIL-SOURCE-FACT-271828`，未分块长输入被拒绝。
- 基础探针：中、英、德、法、西、日、韩、阿各1条问题，在4条明确合成的机制描述中均将对应的掩码语言模型条目排在第一。四条候选和全部分数均保存。只有8条基础探针，不能当作方案要求的8语160题论文检索验收。
- 独立核对：同目录`independent-model-audit-20261020T025012487410Z.json`，36项通过。绕过生产适配器及FastEmbed，直接使用ONNX Runtime、原始分词器、attention mask、均值池化和归一化重算所有探针分数与排序，逐项一致；重新核对下载收据、真实模型字节、英文模型保留及脚本指纹。
