# 多账号持续验收器与短预检

## 实际验收方式

新增真实回环HTTP驱动器、独立服务夹具、5浏览器上下文脚本及标准库进程树内存采样。服务使用当前API和真实解析/活动worker；夹具控制接口只出现在独立测试实例，用户8765服务不增加控制入口。没有为测试替换PDF解析、账号鉴权、数据导出或向量编码结果。

`scripts/concurrency_acceptance.py`默认执行冻结契约的5分钟预热、5账号30分钟、10账号15分钟及3轮60秒负载/30秒回收观察；`--quick`只作短预检，报告固定为`sustained_accepted=false`。正式模式另逐页核对541页教材、p95门槛、内存回收和源码指纹，不能将短预检当成完整验收。

负载包含同名不同内容/相同内容PDF、重复提交、CSV/图形创建及下载、固定旧解析读页、旧研究检查点/导出、全库和指定原文检索、实际本地向量缓存、取消及逐页重试。其他账号标记作为搜索输入时，仅排除正常的查询回显，返回来源仍必须没有其他账号内容。每个账号须实际完成本地向量编码，忙碌响应单独统计，不能让关键词降级冒充向量通道。

后台故障检查先让真实541页任务保存若干页，再停止并重启实际活动worker，验证已有页面ID/坐标及合成中断研究检查点保留。合成研究状态明确标识`fixture_only`，不声明为模型答案或真实付费请求。部分长书取消后保留旧页，再用新解析继续验收；接口确认时间和是否观察到运行中取消分别记录。

5个浏览器同时维持独立登录，在原文文字、源页高亮/返回、结构区及自己CSV之间循环；保存实际首末操作时间及并行区间，不能以顺序操作证明并发。浏览器流量限定同一回环服务。服务及子进程网络限定回环，关闭模型配置且最终核对全部空间模型调用表为空。
