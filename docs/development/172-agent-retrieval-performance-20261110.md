# 本地证据检索耗时与原文定位复测

本轮以 `623db3a` 为基线，使用 BERT v2（`1810.04805v2.pdf`）和 Transformer v7（`1706.03762v7.pdf`）的既有解析版本，分别测量单篇及双篇检索。测量入口是 Agent 的 `search_evidence` 所调用的 `retrieve_for_question`。两版使用同一固定英文查询、返回上限 8、相同 PDF 和解析版本、同一本机 BGE 模型，关闭查询扩展。计时涵盖块读取、BM25、本地向量和 RRF 排序，不含任务排队、工具回执组装、回答生成或 PDF 核验。

机器为 Windows、i7-11800H（8 核 16 线程）、Python 3.12.3、FastEmbed 0.9.0。每种场景独立启动新 Python 进程和空向量库，记录首次检索，再连续测量同题 5 次。优化前后各做两轮，表中首次为 2 次中位数，重复为 10 次中位数，单位为秒。单次波动仍存在，Transformer 的第一轮重复检索慢于旧版，第二轮更快。

| 检索范围 | 首次：优化前 → 优化后 | 重复：优化前 → 优化后 |
| --- | ---: | ---: |
| BERT | 22.7006 → 15.3037 | 0.2240 → 0.1433 |
| Transformer | 13.0851 → 9.3656 | 0.1647 → 0.1540 |
| 两篇合检 | 29.6747 → 21.6464 | 0.3104 → 0.2363 |

首次检索中，原文段落向量编码及模型初始化占优化前耗时约 97%–98%。基线按场景编码 396、304、697 个去重后的文本片段。优化保留模型、编码输入和批次，在至少 8 个逻辑 CPU 的环境中将每个 BGE 会话的 ONNX 线程预算从 2 提到 4。资源较少时最多使用 2 个线程，单 CPU 环境使用 1 个。Python 3.13 及以上优先采用进程可用 CPU 数，旧版采用系统逻辑 CPU 数。首次段落编码（含初始化）中位耗时分别从 22.2754、12.6567、29.0784 秒降到 14.9038、8.9758、21.0672 秒。

重复检索复用原文向量，词法排序则仍需按当前查询计算。BM25 每次查询只计算一次各词的逆文档频率，跳过无匹配的块，复用已计算的质量权重和原文分词计数。词法排序中位耗时从 74.2、42.1、88.9 毫秒降到 22.9、20.5、32.4 毫秒。优化保留原计分顺序、质量规则、结果顺序和向量缓存键。

两轮共核对 288 对新旧结果。命中顺序、分数、文献与解析版本、块 ID、原文文本、PDF 页码和高亮坐标一致。裁剪原 PDF 核对每条返回文本，两篇单篇查询均在第 2 条命中 PDF 第 3 页的结构正文。另走实际 `AgentTools` 和本地 FastAPI，24 条回执对应的原文块与位置均可核对，页图像素与直接渲染源 PDF 一致。用旧版双篇向量库的隔离副本执行新版检索，三个场景分别命中 437、539、976 个片段，新增与重编码均为零。

539 项相关本地回归通过，覆盖向量缓存、阅读区、Agent 工具和工作流、引用与审核、图谱、文献库和 API。执行耗时 82.44 秒，有一项已有的 Starlette TestClient 弃用警告。此处记录的是相关回归范围。

复现脚本为 `scripts/benchmark_agent_retrieval.py`。下列命令使用已保存的验收快照，结果目录应尚不存在。可在两版源码上分别运行同一脚本，再用 `--baseline` 指向旧版的结果目录核对。每个场景的 `results.json` 含逐次耗时、各阶段计时、缓存状态、固定解析版本及命中位置。段落编码计时含模型加载，二者不可直接相加。

```powershell
.\.venv\Scripts\python.exe scripts\benchmark_agent_retrieval.py `
  --source artifacts/live-agent-flash-retest-20261110-150356 `
  --output .runtime/agent-retrieval-perf-20261110/reproduction
```

本地原始记录位于 `.runtime/agent-retrieval-perf-20261110/`。两轮目录分别为 `baseline-v2`、`optimized-v1` 和 `baseline-v3`、`optimized-v2`。实际工具与 PDF 接口核验为 `tool-to-pdf/results.json`。验收只使用本地论文、模型文件和数据副本，未调用远程生成模型，未覆盖旧交付件或修改运行中的主库。结果仅代表这台机器与这三条查询，不作为其他硬件、长文献或多并发情形的性能承诺。
